# Improvised Behaviour

Outpost v1.51 shipped unfinished, and parts of the original are not decoded
yet. Where the rebuild needs behaviour it cannot take from OUTPOST.EXE, it
improvises, and every such place is listed here and tagged `IMPROVISED` in
the code (`grep -rn IMPROVISED rebuild/src`). Nothing here should be read as
original behaviour. When the original code is decoded, the entry is
replaced by the real thing and removed from this list.

Kinds:

* **Stand-in** — the original does this in code we have not decoded yet;
  the rebuild uses a simple substitute with the same intent.
* **Guard** — the original would crash, hang or divide by zero; the rebuild
  does the least surprising thing instead.
* **Gap** — the original game never implemented it (to be filled in only
  when a feature needs it, and designed to fit the original's rules).

Gaps in the original (left as they are; candidates for an optional
"completion" mode later, which would be listed here first):

* Scheduled disasters 1–6 (earthquake, volcano, meteor, solar flare,
  sandstorm, electrical storm, by the cheat dialog's list) only post a
  message: OUTPOST.EXE v1.51 contains no damage code for them (`s6:9114`).
* The Ship Configuration dialog cannot load anything as shipped (I24):
  `ShipConfig::open` reproduces it, `openImproved` is the way in.

Not improvised, but not modelled yet (inputs the tests set directly, or
that come from a loaded save, `sim/ops_loader`): a new game's sites (the
galaxy, star and planets are made by `sim/new_game`; the planet's sites are
map work), the current planet's hostility for SCMorale
(`Simulation::setPlanetHostility`; a save provides it),
the satellites and probes launched from orbit in the UI
(`Simulation::launchOrbital`, `s3:6604`; the ship dialog's own launch is
`sim/ship_config`), the morale-crisis dialog answer
(`Simulation::moraleCrisis`), the colony hub (`Colony::hub`; saved), police
mode and lab topics chosen in the UI (saved), the building windows' detail
buttons (Needs, Master, Details, Help; they say "not available yet"), the site's mine sites in a
new game (`Simulation::hiddenDeposits`; a save holds only the revealed
ones, so explorers find nothing more after loading), AI manager assignments
(`Simulation::aiManagers`), trade agreements and units placed or moved
by the player. A save (`sim/ops_loader`, `sim/ops_writer`) carries the
mothership's lists, the AI managers, trade agreements, units and the
automatic-trucking option and orbital objects as well; the crisis answer
is not saved. The player's truck routes (`s8:1C3E`) and the
vehicle manager's trips (`s8:7A76`) are modelled (`sim/vehicles`); routes
are set in the UI, and trips are not saved yet (I23). The monorail trains
(`s7:AFFC`) are modelled and completed where the original is unfinished
(I26–I28).
