# The Map: Sites, Grids and Terrain (decoded 2026-10-12)

Every statement cites the function it was read from in
`reference/outpost-exe/disasm`. Rebuild: `rebuild/src/sim/map.*`,
`rebuild/src/data/site_maps.*`, tests `rebuild/tests/test_map.cpp`.

## 1. The map object

`DGROUP [0x5740]` is the map: a list (`+0x04`) of **grids**, one per site.
`s7:677A(map, site)` finds the grid whose `+0x24` is the site handle.

| Function | Meaning |
|----------|---------|
| `s7:6222(map, placeMines, record, site)` | new grid (0x4C bytes, ctor `s7:88CE`) appended to the list; with `placeMines` the record's mine sites become DisMines (`s7:8D08`) |
| `s7:627E(map, pos, site)` | the tile handle on a cell, or 0 |
| `s7:64CE(map, pos, site, &out)` | the cell's raw value (tile handle or terrain number) |
| `s7:61FE(map, tile, pos, site)` | put a tile handle on a cell (`s7:8AA0`) |

Callers that make grids: a new site (`s6:ED2C`: `s7:4782` generates the
record, then `s7:6222(…, 1, …)`), and loading a save (`s6:E7F3`: for every
loaded site, `s7:6222(…, 0, site+0x10, site)`).

## 2. Grid

```
+0x04..+0x22  copy of the site record (s7:8544): +0x12 = record +0x0E, the
              terrain DIB; +0x1A/+0x1E = record +0x16/+0x1A, the mine sites
+0x24         site handle
+0x28         rect (0, 0)-(w-1, h-1) from the DIB header (s2:4772)
+0x34         cell count w * h
+0x38         5 sparse tables, one per level 0..4 (s7:85BE(25, 100))
```

A position is 3 words, unpacked by `s2:3EB4` as **x = word 0, y = word 1,
level = word 2**; y counts rows from the top (`s2:4544` flips the
bottom-up DIB). The cell index is `y * width + x` (`s7:8D9E`), unchecked;
`s7:8CD2` accepts levels 0..5, and level 5 reads past the five tables.

**A cell's value** (`s7:8B00`) is the tile handle stored there, or, when
there is none, the terrain (`s7:8C66`): the DIB pixel `p` gives building
type `p + 1` (Clear 1 .. 4) on the surface, and underground `p = 0 -> 7`,
`1..2 -> 8`, otherwise `9`. A value whose type byte is 0 is terrain;
callers test the type byte (`s7:627E`, `s6:8920`).

## 3. Sites

**The site table** (`DGROUP 0x65E6`, 70 rows of 10 bytes) is filled at
startup by `s7:3B28` from code immediates: row = {planet-view position
(3 words), terrain bitmap id, picture bitmap id}. The rebuild reads it from
the player's EXE by matching that code (`data::readSiteTable`).

**The bitmap catalog** (far data segment 10, through `DGROUP [0x63F0]`):
16-byte entries, id `n` at `(n + 1) * 16`: `+0` kind (1 = bitmap file),
`+2` DGROUP offset of the file name (`s3:830A`, `s3:8018`). Site `i` has
terrain id `347 + i` and picture id `277 + i`:

| Site | Terrain map (record +0x0E) | Picture (record +0x12) |
|------|----------------------------|------------------------|
| 0 | `500a.bmp` | `500.bmp` |
| … | `5xxa.bmp` | `5xx.bmp` |
| 69 | `579a.bmp` | `579.bmp` |

The 70 sites use 500–579 **without 529, 530, 533–540**; all 140 files are
the CD's 300×150 bitmaps. `5xxA.BMP` is **data**, not an animation frame:
its pixels are terrain codes (0..3 only; 54 maps use all four).

**Site record** (0x20 bytes, generated by `s7:4782(sim, genMines, named,
index)`): `+0x00` site index, `+0x02` a number from the planet (`s7:2A98`),
`+0x04` name (string 1581 formatted with it), `+0x08` the row's position,
`+0x0E` terrain DIB, `+0x12` picture, `+0x16` mine positions, `+0x1A`
visible mine sites, `+0x1C` hidden ones. With `genMines`: `n = random`
over the planet's range (`s7:2F1A`; 15 without a planet, "get site data
without planet!"), hidden = `n * 10 / 100`; visible = `factor * n / 100`
with factor 60, or 90 on Beginner/Easy with an orbital of kind 0x84 up; on
Medium/Hard the orbital count 1..4 adds 8/15/23/30. All positions are
random `(random(0, w-1), random(0, h-1))` on the surface, distinct.

## 3a. Placement: SCInternalPutBldg (`s6:87F0`, `s6:8920`)

The step does all its work in **slot 2 (`shouldRun`, `s6:8920`)**, which
`Sim::enqueue` calls on the caller's own object before cloning it; its
`calcMe` is the empty `SCBase` default (`s6:D222`). So a building is placed
the moment the step is queued, and the queue only gets a no-op at priority
1000. (That is why the AI builder can read the new building at `+0x120`
right after queueing, `s7:9FF8`.)

Step fields: `+0x108` site, `+0x10C` colony, `+0x110` player for a new
colony (SCInternalPutBldg2 only), `+0x114` position, `+0x11A` type,
`+0x11C`, `+0x11E` flags, `+0x120` the new building.

1. Cell value at the position (`s7:64CE`). A tile handle: use that tile.
   Otherwise a new **tile** (`s6:EE54` → `s7:684C`): owner = the site,
   `+0x0C` position, `+0x12` and `+0x14` = the cell's terrain number; put on
   the grid (`s7:61FE`). For type 10 (Seed) or 55 (Command) a new **colony**
   (`s6:EDC4` → ctor `s8:3222`) owned by the site, whose **hub** (`+0x10`) is
   the cell's value, i.e. the new tile; view registration `s4:0196`; player
   from `+0x110` if set. For 55 the step's old colony is kept as the parent.
   The colony adds the tile (slot 2, `s8:5860`, skipping duplicates).
2. `s7:73EE`: tile `+0x2A` = colony handle (also for an existing tile).
3. Tile `+0x14` = 5, or 6 below ground, unless the type is terrain (group
   49) or `+0x11C` is set.
4. The old building to SCKillBldg; the new one created (`s6:E2E0`) and set
   on the tile; slot 1 (owner), slot 8, slot 6 with arg 1.
5. Type 55: building `+0x20` = the parent colony. `+0x120` = the building.

Creator table of the object DB (`db+0x2E`, set by `s6:D81C`): type 1
`s6:EC36`, 2 `s6:ECAC`, 3 (site) `s6:ED2C`, 4 (colony) `s6:EDC4`, 5 (tile)
`s6:EE54`, 6 (unit) `s6:EF00`, 7 (building) `s7:10B0`, 8 `s7:1120`.

**Incidents** (`s6:6B40`) wreck the 8 neighbours clamped to the site's map
(`s6:6DAA` → site `+0x14` size), both axes with the width (quirk Q51), in
the order (x-1,y-1), (x,y-1), (x+1,y-1), (x-1,y), (x+1,y), (x-1,y+1),
(x,y+1), (x+1,y+1); terrain (1–9) and robots (115–121) are spared
(`s6:6D24`).

**Explorers** (`s8:4918`) move one mine site from hidden (`+0x1C`) to
visible (`+0x1A`) and put a DisMine (16) on position `rec+0x16[visible-1]`
through SCInternalPutBldg, unless a non-terrain building is there.

## 3b. The AI managers' placement search (implemented 2026-10-12)

`s7:9F7A(builder, type)`: position = 0 (the surface), then `s7:A278`. Only
when that returns 1 is the building put there (SCInternalPutBldg) and
recorded in the builder; for an underground type (group 40) `s7:A044` then
works on the levels below (not decoded yet).

`s7:A278(builder, &pos)` builds in stages, one piece at a time; the
builder waits (`s8:354A`) until the piece is done:

1. `s7:AA18` → 1: a **ready cell**. For each of the colony's tubes (group 7
   on the surface, 8 below; any state; tile order) inside the map margin
   (`s7:ADDC`: 2 ≤ x ≤ w−2, 2 ≤ y ≤ h−2), a neighbour holding type 5 or 9
   (`s7:ACBE`, bulldozed/dug ground): X tubes (122, 127) try (x,y−1),
   (x,y+1), (x−1,y), (x+1,y); L tubes (123, 126) (x,y−1), (x,y+1); R tubes
   (124, 125) (x−1,y), (x+1,y).
2. `s7:A3AE`: a **tube**. A type 5/9 tile (group 69) at the level, inside
   the margin, with a neighbour holding a group-70 building (`s7:AD22`;
   order (x,y−1), (x,y+1), (x−1,y), (x+1,y)) gets an X tube (122, or 127
   underground) on its own cell.
3. `s7:A57E` (needs an available Dozer, `s8:53BA` kind 1): the same tube
   scan as 1 for an **empty buildable** neighbour (`s7:AD86`: no tile and
   terrain 1–3 or 7–8) → a RoboDozer (115, or 119 underground).
4. `s7:A844` (also needs a Dozer): any group-70 building at the level,
   inside the margin, with an empty buildable neighbour (same order) → a
   RoboDozer.

The piece is queued through SCInternalPutBldg (site = colony `+0x08`) and
the builder's tile is set to it; underground also `s7:A044`.

**RoboDozer** (types 115/119; ctor `s5:E91E`): placement puts it in state
1 (`s5:EA0E`); its reserve (`s5:E9D4`) attaches it to a RoboCmd robot
(`s7:DF0C`) and marks a Dozer busy (`s8:57DC`: colony `+0x1A2[kind] += n`).
In state 1 `+0x14` is a turn counter, from the tile's `+0x14` mark (5, 6 →
1 turn; `s5:ECB0`). Each construction tick (`s5:ED3C`) counts down; at 0:
state 0, tile mark = 5 (surface) / 6, the cell becomes type 5 (surface) or
9 (`s5:EE3A`), the Dozer is freed (`s8:5804`), and with `+0x24` set some
sewage is queued (SCAddSpew).

## 3c. Planet::genKids and the new site (implemented 2026-10-12)

`s7:3058`: for each id of the planet's site list (record `+0x22` count,
`+0x24` ids) the site creator `s6:ED2C` makes a Site (ctor `s7:565A`, owner
the planet), its record (`s7:4782(sim, genMines 1, named 1, id)`), sets it
(`s7:5A80`: site `+0x14` = (w, h, 1) from the terrain DIB), and its grid
with DisMines (`s7:6222(map, 1, …)` → `s7:8D08`: a tile and a DisMine
building, no colony, on each of the first `+0x1A` positions, level 0).

In `s7:4782`: the name is string 1581 "Site %d" with n = `++planet+0x14`
(`s7:2A98`); the mine-site count `n = random(lo, hi)` by the planet's
hostility (`s7:2F1A`: 1, 2, 8, 9 → 25–45; 3–5 → 10–15; 6 → 10–25;
7 → 25–55; else 0–0). Rebuild: `Simulation::generateSites`.

## 3d. The player's placement rules (base implemented 2026-10-12)

Building slot 7 (`+0x1C`, args building, position, colony, site) answers
"may it go here?"; on refusal it leaves a string id in DGROUP `0x50CA` and
an argument in `0x50CC` (strings 1703–1720). Base `s6:BC90`:

1. `s6:C7B6` cell kind must be 5 or 6, else **1704** "That is not possible
   on this terrain." Kind: an empty cell's terrain; a tile's terrain
   building 1..9 → 1, 2, 3, 4, 5, 7, 8, 9, 6; any other building → 0; a
   tile without a building → its mark `+0x14`.
2. Slot 24 (base `s6:C522`): distance |dx|+|dy| from the colony hub
   (`s7:BCDE`, −1 on another site) < 0 → **1711**; > 30 → **1718** "Out of
   communications range by %d spaces." with d − 30.
3. Slot 23 (base `s6:C64A`): an LPipe (123/126) at (x, y±1) or an RPipe
   (124/125) at (x±1, y), or an X tube (122/127) there (`s6:C5A6`); no
   message when not.
4. `s6:C23E`: a tile of another colony of the same player moves to this
   colony (old colony slot 6 `s7:18F0` blanks its entries, new colony slot
   2 adds it, `s7:73EE` links); another player's tile refuses silently.
5. `s6:C314`: inside the margin (2 ≤ x ≤ w−2, 2 ≤ y ≤ h−2) else **1720**
   "Dangerous Terrain".

The RoboDozer variant (`s5:EA20`) also checks hub range with ComSat and
comm towers (`s6:C3AA`), refuses other colonies' buildings (1719),
constructing ones (1713), Command centers (1716) and robots (1712), asks a
confirmation dialog (`s9:8520`), and clears what it dozes. Decoded
2026-10-18: cell kind 4, 5, 6, 9 refuse (1704), other terrain is fine; on
a building: another colony's 1719, a lander (62/65) still landing 1713,
Command (11, 55) 1716, 66/75/107 1713, DisMine 16 and 110 silently,
robots 115..121 1712; else (after the dialog; "No" leaves message 1) the
tile's Bas and units are cleared, the building wrecked (slot 9) and
killed, and the dozer keeps the building's BLDGBLD +0x96 (its sewage).
SCPutBldg puts down the candidate it asked, so a direction or amount set
by slot 7 stays on the placed robot. Overrides by
other classes are implemented (`building.cpp`): landers and the Seed
(`s6:09D4`, `s6:2C28`), Command centers (`s7:C52E`), comm towers
(`s5:D118`), smelters (`s6:38D4`), roads (`s7:DB72`/`DB92`), tubes
(`s6:2844`), UGGeoTherm (`s6:567C`, always refuses, Q55), monorails
(`s6:1CCA`/`1DA4`: a 22 piece above/below, a 23 piece left/right, or 24/63
either way; site-only range) and MonoStations (`s6:2290`/`23A8`: 22/23 or
a MonoXFormer 64, Q58), the RoboMine (`s6:1824`: a DisMine on the surface,
1707 below; a UG mine 96/97 above the planet's maximum depth, 1708, with
diggable ground below; else 1706) and the RoboDigger (`s5:DA4E`: not on a
DisMine, 1705; range `s5:DB86` limited to 30 only underground; surface
cells of kind 1..3, 5 dig down, kind 4 asks the direction dialog;
underground only an air core digs down (Q57), dug ground 6..9 asks the
direction: sideways needs a cell of kind ≠ 0 next to it, 6 fills in).
The planet's maximum digging depth (`s7:2FAC`) by hostility: 0..1 → 4,
2..4 → 3, 5..7 → 2, more → 1. The police mode and digger direction
dialogs are UI: the rebuild takes the value the caller set.

## 3e. Robots at work and the vehicle manager (implemented 2026-10-12)

* **RoboDigger** (116, 120, 121; `s5:D99E` family): starts in state 2;
  turns by the marks of its cell and the next (`s5:E4FA`); a type-120 side
  tunnel puts a 121 piece; when done the cell becomes Core 71 / UGCore 106
  (down), dug ground by mark (sideways), or 1/6 with a cave-in (fill,
  `s5:DCA8`); digging down deepens the site and puts a UGCore below; the
  ground around softens (`s6:CCD0`, 9→8→7→6).
* **RoboMine** (117): claims a Miner (`s6:17D8`), state 2, 7 turns
  (`s6:1B1E`); then a mine (51 on the surface, 96 below) on its cell and a
  UG mine 96 one level down, the site deepened (`s6:199A`).
* **RoboExplr** (118): its reserve (`s6:2B46`) is empty; base class.
* **AI underground link** `s7:A044`: below the surface the ground around
  a new piece softens as after digging.
* **Truck routes** (`s8:1C3E`, from SCMove for every colony tile with
  trucks `+0x34` and a route `+0x36`): a waiting load on the tile (`+0x3A`,
  `s8:201A`) goes first; else smelters (`s8:24E8`, output ledger entries
  visited once, 100 units a truck), mines (`s8:26EE`, ores round the
  mine's cycle) and factories (`s8:2306`, an output item per truck).
  Trucks are counted off the tile, at most `+0x32` (`s7:6C4C`).
* **Trips** (0x2A bytes, `vehicles.hpp`): route copy, home tile, one kind
  of load (Bas, a cargo table, product A or B, quantity), position, next
  stop, movement points (+60 a turn), trucks, a waiting flag. A step goes
  along x, then y, then a level (only from a Core/UGCore); its cost by the
  cell (`s8:6E1A`): terrain 1→20, 2→60, 3→120, 4→240, 5,6→15, 7→60,
  8→120, 9→240; buildings 1..9 by kind, group 0x41 → 12, group 0x42 or a
  MonoStation → 10, others → 15; an empty cell 1. A stop that is a
  monorail stop (group 0x40) makes the trip wait for a train. At the last
  stop (`s8:7356`) warehouses take products that fit, storage tanks Bas
  that fits, other buildings anything; what does not fit stays on the
  tile (`s8:709C`: its `+0x3E` list, product-A units as well). The trucks
  go home at once. Movement reads the site in view (I25).
* **Monorail trains** (vehicle manager list `+4`, 0x14 bytes, ctor
  `s7:AEFA`): made when a MonoStation finishes next to a MonoXFormer 64
  (`s6:20B6` → `s8:79B2`), dropped with the station (`s6:2042`). Fields:
  station tile `+4`, position `+8`, direction `+0x0E` (1 y-1, 2 x+1, 3 y+1,
  4 x-1; 0 → the first rail round it, `s7:B344`), riders `+0x10`. Each turn
  (`s7:AFFC`) up to 6 cells along rail (group 0x42 = 22, 23, 24); a piece
  of the wrong axis stops it. At a crossing or station `s7:B142` picks the
  way; at a stop (group 0x40 = 63) `s7:B454` drops riders whose next stop
  it is and boards waiting trips up to 500 (`s8:6984` weights: Bas 1, a
  cargo table its total, products quantity × unit value). The rail pieces
  under a train get `+0x20` = 1 (drawn as the train sprites 25/26).
  Unfinished in the original (Q62): stations are not rail, the junction
  masks (`s6:1C1C`, `s6:20B0`) and the load (`s7:B13C`) are stubs, and
  only a loaded save fills a station's waiting list. The rebuild completes
  these (I26–I28).

## 4. Corrections to earlier documents

* `00-ground-truth.md §5` and the Phase 002 remaster call `500.bmp…579.bmp`
  + `500a…579a.bmp` "A/B animation frame pairs" of building sprites. They
  are the 70 **site** pictures and terrain maps. The remaster's ten
  "buildings without a sprite" (529, 530, 533–540) are just the numbers no
  site uses.
* `contracts/tilemap-format.md` ("no tile array") is superseded: the map is
  a sparse grid of tile handles over a terrain bitmap.
